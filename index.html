Welcome

Hello, Future Programmer

Every wizard starts as an apprentice.

Somewhere near you is a machine that can count faster than you can blink, remember more words than you will ever read, and follow instructions with perfect patience. That machine is a computer. But it is also a very silly machine. It can do almost nothing on its own. It needs you to tell it exactly what to do — one tiny step at a time.

Those tiny steps are called code. And the person who writes them is called a programmer. That, very soon, will be you.

This book is a journey in three parts:

  • Part One — Adventurers. You will meet the computer, learn its tiny vocabulary, and make it do your bidding. Perfect for ages five to eight.
  • Part Two — Explorers. You will discover lists, treasure chests, and the grand playground of the web. Great for ages nine to eleven.
  • Part Three — Masters. You will build your own tools, tame time, and speak to the internet. For ages twelve and thirteen.

You do not need a fancy setup to follow along. Any tool that runs JavaScript — a browser, a code editor, a friendly app — will do. The examples in this book are little seeds. Plant them, water them, break them, fix them, and grow them into something of your own.

Ready? Let us begin.

Before You Go

  • A program is a set of instructions for a computer.
  • A programming language is the way we write those instructions.
  • JavaScript is one such language — and it lives in every web browser.
  • You do not have to be a genius. You have to be patient and curious.

Warm-Up Questions

  1. What is one thing you wish a computer could do for you?
  2. Can you think of three machines in your home that have a tiny computer inside?
  3. What does the word "instruction" mean to you?

Part One · Adventurers · Chapter One

Hello, Computer!

The very first words you will teach your new machine friend.

Imagine you have a tiny robot named Pip. Pip is very fast and very strong, but Pip is also very literal. If you say, "Make me a sandwich," Pip might stare at you blankly. If you say, "Take one slice of bread, place one slice of cheese on top, then place another slice of bread on top," Pip will happily obey — in less than a second.

A computer is like Pip. It is not clever. It is not creative. It only follows instructions. The instructions have to be broken into very, very small steps.

A program is a list of those small steps. The act of writing them is called programming. When you write a program, you are the boss. The computer is the loyal assistant.

Here is the simplest program in the world. It tells the computer to show a message:

console.log("Hello, world!");
// → Hello, world!

Read it out loud like a sentence. "Console dot log: Hello, world!" The part in quotes is the message. The console.log is the instruction that says "show this on the screen." The // and the arrow show what happens when the program runs. Go ahead. Type it into any JavaScript console. The machine will say hello back.

You have just had your first conversation with a computer. It is that simple — and it is that powerful.

Key Ideas

  • A program is a list of precise instructions.
  • Computers follow instructions exactly — no more, no less.
  • console.log is how you ask the computer to show a message.
  • The quotes around a message are not part of the message; they mark where it starts and ends.

Try It Yourself

  1. Write a program that prints your name.
  2. Write a program that prints two different messages on two different lines.
  3. What do you think happens if you forget one of the quotation marks? Try it and see.

Part One · Adventurers · Chapter Two

Words, Numbers, and Truth

The three basic ingredients of every computer recipe.

Inside a computer, everything is made of tiny pieces called values. Think of them as the different kinds of LEGO bricks a programmer can snap together. There are many kinds, but three are especially important for beginners: numbers, strings, and booleans.

Numbers are exactly what you think they are: 1, 2, 3, 42, 100, even 9.81. You can add them, subtract them, multiply them, and divide them. The symbols +, -, *, and / work just like in math class.

console.log(2 + 3);   // → 5
console.log(10 - 4);  // → 6
console.log(6 * 7);   // → 42
console.log(20 / 4);  // → 5

Strings are pieces of text — words, sentences, names, anything in quotes. The quotes can be single ('...'), double ("..."), or backticks (`...`). It does not matter which, as long as you use the same kind at both ends. You can glue two strings together with the + sign, like this:

console.log("Hello, " + "world!");
// → Hello, world!

Booleans are the simplest of all. They have only two possible values: true and false. They are how computers think about yes and no. Booleans are what you get when you compare two values:

console.log(3 > 2);   // → true
console.log(3 < 2);   // → false
console.log(3 === 3); // → true

That's it. Numbers, strings, booleans. With just these three, you can already make the computer do useful arithmetic, display messages, and make simple decisions.

Key Ideas

  • Numbers are for counting and math.
  • Strings are for text, and must be wrapped in quotes.
  • Booleans are true or false, and come from comparing things.
  • The + sign can add numbers or glue strings together, depending on what it is given.

Try It Yourself

  1. Use console.log to print the result of 12 * 12.
  2. Print the string "I am learning JavaScript".
  3. Is the value "5" + 1 the same as 5 + 1? Try both and see.

Part One · Adventurers · Chapter Three

Name Tags for Things

How programmers remember things without a notebook.

Imagine you are baking cookies. You have a bowl of sugar, a bowl of flour, and a bowl of chocolate chips. Every time you need sugar, you look for the bowl labeled "sugar." That label saves you from dipping your spoon into the wrong bowl.

Programmers need labels too. A label for a value is called a binding, or sometimes a variable. You create one with the word let, give it a name, and put a value inside it:

let myAge = 10;
console.log(myAge); // → 10

Now, any time you use the word myAge, the computer knows you mean the number 10. You can even change what the label points to:

let myAge = 10;
myAge = 11;
console.log(myAge); // → 11

But what if you want a label that can never change? Then use const instead of let. A constant is like a name carved into stone:

const birthday = "May 3rd";
// birthday = "June 1st"; // this would be an error!

Good names matter. A name like x tells you nothing. A name like myAge or cookieCount tells you exactly what is inside. Choose names that read like tiny sentences.

Imagine your labels as little name tags stuck onto values. The values themselves can live anywhere; the tag is how you find them again.

Key Ideas

  • let creates a label whose value can change later.
  • const creates a label whose value cannot be changed.
  • Use clear, descriptive names — your future self will thank you.
  • Names cannot have spaces or start with a number.

Try It Yourself

  1. Create a binding called myName and set it to your name. Print it.
  2. Create a constant called favoriteColor and set it to your favorite color.
  3. What happens if you try to change a const after it is set?

Part One · Adventurers · Chapter Four

Making Choices

How computers decide what to do next.

Every morning you make a choice. You look outside. If it is raining, you take an umbrella. If it is sunny, you take sunglasses. You do not need a long speech — just a quick glance and a decision.

Computers make choices the same way, using a word called if. The word is followed by a question and, depending on the answer, a set of instructions to follow or skip.

let isRaining = true;

if (isRaining) {
  console.log("Take an umbrella!");
}

If the question is true, the message appears. If it is false, nothing happens.

Often you want two paths — one for yes, one for no. That is what else is for:

let isRaining = false;

if (isRaining) {
  console.log("Take an umbrella!");
} else {
  console.log("Take sunglasses!");
}

You can even chain several choices together. Imagine a game that greets you differently depending on your score:

let score = 75;

if (score >= 90) {
  console.log("Amazing!");
} else if (score >= 60) {
  console.log("Well done!");
} else {
  console.log("Keep practising!");
}

The computer checks each question in order, from top to bottom. The first one that is true wins. This is exactly how you decide what to wear, what to eat, and which path to take home.

Key Ideas

  • if runs a piece of code only when a condition is true.
  • else gives an alternative path when the condition is false.
  • else if lets you chain many possible choices.
  • The curly braces { } group one or more instructions together.

Try It Yourself

  1. Write a program that prints "Good morning" if the hour is before 12.
  2. Write a program that prints "Too hot!" if the temperature is above 30, and "Nice!" otherwise.
  3. What happens if two conditions in a chain are both true?

Part One · Adventurers · Chapter Five

Round and Round We Go

How to make the computer repeat something without getting bored.

Suppose you want to count from 1 to 100. You could write a hundred lines of code, but that would be silly. Programmers are lazy in a clever way: they find shortcuts. The shortcut for repeating something is called a loop.

There are two main kinds. The first is the while loop, which keeps going as long as a question stays true:

let number = 1;

while (number <= 5) {
  console.log(number);
  number = number + 1;
}
// → 1
// → 2
// → 3
// → 4
// → 5

Read it like this: "While the number is less than or equal to five, print it and then add one." Each time through the loop, the number grows by one, until finally it becomes six and the question is false. The loop then stops.

The second kind is the for loop. It is a shorter way to write the same idea, with three parts bundled together:

for (let number = 1; number <= 5; number++) {
  console.log(number);
}

The three parts are: where to start, how long to continue, and how to change after each round. That is it. It is the same logic, just tidied up.

Sometimes you need to stop early. The word break jumps out of a loop immediately. The word continue skips the rest of this round and starts the next one.

Loops are everywhere. They draw patterns, shuffle cards, count coins, and (as you will see later) run games.

Key Ideas

  • A loop repeats instructions until a condition stops being true.
  • while loops check the condition before each round.
  • for loops group the counter, condition, and update in one line.
  • break exits the loop; continue skips to the next round.

Try It Yourself

  1. Print the even numbers from 2 to 20.
  2. Print "Hello!" five times using a loop.
  3. What happens if the condition in a while loop never becomes false?

Part One · Adventurers · Chapter Six

Magic Machines Called Functions

Write it once. Use it forever.

Imagine a very small machine with a funnel on top and a crank on the side. Drop a number in the funnel, turn the crank, and out comes the square of that number. Drop in 3, out comes 9. Drop in 5, out comes 25. You do not have to know how the machine works inside; you only have to know what it does.

That machine is called a function. A function is a little package of code you write once and call whenever you need it. Here is a function that squares a number:

function square(x) {
  return x * x;
}

console.log(square(3)); // → 9
console.log(square(5)); // → 25

The word function starts the definition. square is the name. x is the parameter — the slot where you drop something in. return is how the function hands its result back to you.

Functions can do anything. They can print messages, calculate totals, even call other functions. Once you have a function, you can use it a hundred times without rewriting a single line.

function greet(name) {
  console.log("Hello, " + name + "!");
}

greet("Ada");   // → Hello, Ada!
greet("Pip");   // → Hello, Pip!

Functions can also be written more briefly, with an arrow. Do not worry about the arrow yet — just know that const square = x => x * x; does the same thing as the long version.

The magic of functions is reuse. You write once, and the whole rest of your program can use the same little machine.

Key Ideas

  • A function is a reusable block of code with a name.
  • Parameters are the slots for input; arguments are the actual values you give them.
  • return sends a result back to whoever called the function.
  • Functions keep your programs short, clear, and easy to fix.

Try It Yourself

  1. Write a function called double that returns twice its argument.
  2. Write a function called isEven that returns true if its argument is an even number, and false otherwise.
  3. Write a function called shout that prints a message in all uppercase letters.

Part Two · Explorers · Chapter Seven

Lists of Things

When one value is not enough.

So far, every name tag held one value. But what if you want to remember a whole shopping list — milk, eggs, bread, apples? You could make four separate bindings, but that gets messy fast. Programmers have a better tool: the array.

An array is an ordered list of values, written with square brackets and separated by commas:

let shopping = ["milk", "eggs", "bread", "apples"];

console.log(shopping[0]); // → milk
console.log(shopping[2]); // → bread
console.log(shopping.length); // → 4

Notice three things. First, the items go inside square brackets. Second, you get an item out by putting its position in square brackets after the name. Third — and this is the one that surprises everyone — the first item is at position zero, not one. Programmers count from zero.

Arrays have superpowers. You can add to the end with push, take from the end with pop, and loop over every item with a for...of loop:

let shopping = ["milk", "eggs"];

shopping.push("bread");
console.log(shopping); // → ["milk", "eggs", "bread"]

for (let item of shopping) {
  console.log("I need " + item);
}

Arrays are the backbone of almost every program you will ever write. They hold the scores in a game, the messages in a chat, the pixels in a picture, the rows in a spreadsheet. Get comfortable with them.

Key Ideas

  • Arrays hold ordered lists of values.
  • Indexes start at 0. The last index is length - 1.
  • push adds to the end; pop removes from the end.
  • for...of visits each item in turn.

Try It Yourself

  1. Make an array of your five favorite foods. Print the third one.
  2. Add a sixth food to the end. Print the length of the array.
  3. Use a for...of loop to print every food with a smiley face.

Part Two · Explorers · Chapter Eight

Treasure Chests Called Objects

Grouping related things together.

An array is great when all its items are the same kind of thing. But what if you want to describe a person — name, age, favorite color, whether they can whistle? An array cannot tell you which item is which. You need a new tool: the object.

An object is a collection of properties, each with a name and a value. It looks like an array, but with names instead of positions:

let ada = {
  name: "Ada",
  age: 12,
  favoriteColor: "teal",
  canWhistle: true
};

console.log(ada.name);           // → Ada
console.log(ada.favoriteColor);  // → teal

You reach into an object with a dot. The dot is like a tiny key that opens one drawer at a time. You can change a value too:

ada.age = 13;
console.log(ada.age); // → 13

You can also use square brackets with a string inside, which is handy when the property name is stored in a variable:

let key = "favoriteColor";
console.log(ada[key]); // → teal

Objects are how programmers model the world. A game character is an object with a position and a health value. A message is an object with a sender and a time. A recipe is an object with a list of ingredients and a list of steps. Once you see objects, you see them everywhere.

Key Ideas

  • Objects hold named values, called properties.
  • Use a dot (object.key) or square brackets (object["key"]) to reach a property.
  • Unlike strings and numbers, objects can be changed after they are created.
  • Use objects whenever related pieces of information belong together.

Try It Yourself

  1. Create an object describing yourself — name, age, and one fun fact.
  2. Print your name from the object using dot notation.
  3. Add a new property called hobby to the object.

Part Two · Explorers · Chapter Nine

Super Functions

When functions can take other functions as gifts.

Here is a wild idea: in JavaScript, functions are values. You can put them in variables, pass them to other functions, and return them from functions. This is not just a curiosity — it is the single most powerful feature of the language.

A function that takes another function as an argument is called a higher-order function. The name sounds fancy, but the idea is simple: you are telling one machine to use another machine as part of its job.

The most common examples live on arrays. The map method transforms every item using a function you provide:

let numbers = [1, 2, 3, 4, 5];

let doubled = numbers.map(n => n * 2);
console.log(doubled); // → [2, 4, 6, 8, 10]

Read it as: "Take this array, and for every item, apply this little function." The array goes in one side, the transformed array comes out the other.

The filter method keeps only the items that pass a test:

let evens = numbers.filter(n => n % 2 === 0);
console.log(evens); // → [2, 4]

And reduce folds a whole array down into a single value:

let total = numbers.reduce((sum, n) => sum + n, 0);
console.log(total); // → 15

These three — map, filter, reduce — are the bread and butter of modern JavaScript. Once you understand them, you can write programs that read almost like English sentences.

Key Ideas

  • Functions can be passed to and returned from other functions.
  • map transforms every item in an array.
  • filter keeps only the items that match a test.
  • reduce combines every item into a single result.

Try It Yourself

  1. Use map to turn [1, 2, 3] into [10, 20, 30].
  2. Use filter to keep only the words longer than three letters in ["cat", "elephant", "dog", "hippo"].
  3. Use reduce to find the largest number in an array.

Part Two · Explorers · Chapter Ten

Oops! Bugs and Errors

Why programs break, and what to do about it.

Nobody writes perfect code. Not you, not me, not the engineers who landed a robot on Mars. Every programmer, every day, writes mistakes. These mistakes are called bugs, and finding them is called debugging.

There are three kinds of bugs you will meet:

  • Syntax errors. The computer cannot even understand what you wrote. Maybe you forgot a quote or a closing brace. The program refuses to run.
  • Runtime errors. The program starts, then hits a problem. Perhaps you tried to read a property from something that is not an object.
  • Logic errors. The program runs happily but does the wrong thing. These are the sneakiest of all.

JavaScript lets you signal a problem with the word throw:

function divide(a, b) {
  if (b === 0) {
    throw new Error("Cannot divide by zero!");
  }
  return a / b;
}

And you can catch such problems with try and catch, so your program can keep going instead of crashing:

try {
  console.log(divide(10, 0));
} catch (error) {
  console.log("Something went wrong: " + error.message);
}

When your program misbehaves, do not panic. Read the error message carefully. Add a few console.log lines to peek at what your values actually are. Run small pieces of code at a time. And keep in mind the most important debugging tool of all: patience.

Key Ideas

  • Bugs are mistakes in code; debugging is the art of finding them.
  • throw raises an error; try / catch handles one gracefully.
  • Error messages are your friends, not your enemies — read them slowly.
  • Small experiments are the fastest path to understanding.

Try It Yourself

  1. Write a function that throws an error if its argument is negative.
  2. Call that function safely, catching the error and printing a friendly message.
  3. Introduce a typo in an earlier program. What does the error message say?

Part Two · Explorers · Chapter Eleven

The Web Playground

How JavaScript brings a web page to life.

Every web page you visit is a little scene made of HTML — the structure, the text, the buttons, the pictures. JavaScript can step onto that scene and rearrange it. It can change text, add images, hide things, show things, respond to clicks.

The browser hands JavaScript a model of the whole page, called the DOM — the Document Object Model. The DOM is a tree. Every element on the page is a little node in that tree: the heading, the paragraph, the link, the image. JavaScript can find any node and change it.

let heading = document.querySelector("h1");
heading.textContent = "Hello, new world!";

That little line finds the first heading on the page and changes its text. In one command, the visible page has changed.

JavaScript can also listen for things the user does. Clicks, keypresses, mouse movements — these are called events. You attach a function to an event, and the browser calls your function when the event fires:

let button = document.querySelector("button");

button.addEventListener("click", () => {
  console.log("You clicked the button!");
});

You can build forms that respond as you type, buttons that toggle the lights, games that react to every key. This is what makes the web feel alive.

Everything that is possible in a browser is possible because of these two ideas: the DOM (a tree you can edit) and events (moments you can react to). Master them, and the web becomes your canvas.

Key Ideas

  • The DOM is a tree of page elements that JavaScript can inspect and change.
  • querySelector finds an element by CSS selector.
  • addEventListener registers a function to run when an event happens.
  • The browser is a live playground — change the DOM, and the page changes.

Try It Yourself

  1. Add a button to a page and log a message when it is clicked.
  2. Find a paragraph and change its text using textContent.
  3. Make a button that, when clicked, changes the page background color.

Part Three · Masters · Chapter Twelve

Building New Things

How to invent your own kinds of values.

JavaScript comes with numbers, strings, arrays, and objects. But a growing program needs its own building blocks — a Vector for 2D games, a Robot for a simulation, a Player for a character. You can build these yourself with classes.

A class is a blueprint. It describes what a kind of thing should have and what it should be able to do. Then you create instances of the class — actual things built from the blueprint:

class Animal {
  constructor(name) {
    this.name = name;
  }

  speak() {
    console.log(this.name + " makes a sound.");
  }
}

let cat = new Animal("Whiskers");
cat.speak(); // → Whiskers makes a sound.

The constructor is a special method that runs when you create a new instance. The word this inside the class refers to the particular instance being built or used. Methods defined inside the class become shared by every instance.

You can build on top of an existing class with extends. This is called inheritance. A Dog class can extend Animal and add its own behavior while keeping what the parent already knows:

class Dog extends Animal {
  speak() {
    console.log(this.name + " barks!");
  }
}

let rex = new Dog("Rex");
rex.speak(); // → Rex barks!

Classes are how modern JavaScript programs model complicated things. A user, a comment, a game level, a shopping cart — each becomes a class with its own responsibilities.

Key Ideas

  • A class is a blueprint; an instance is an object built from it.
  • constructor runs when the instance is created.
  • this points to the current instance.
  • extends lets a class reuse the behavior of another.

Try It Yourself

  1. Create a Book class with title and author, and a method that describes the book.
  2. Create a PictureBook class that extends Book and adds an ageRange property.
  3. Create two instances and print their descriptions.

Part Three · Masters · Chapter Thirteen

Waiting Games

How JavaScript handles things that take time.

Some things take a while. Fetching a file from the internet, reading from a disk, waiting for a user to type — these are slow compared to how fast a computer can think. If your program froze every time it waited, the whole page would lock up.

JavaScript solves this with asynchronous programming. Instead of waiting, your code says: "Here is what to do when the answer comes back." Meanwhile, the rest of the program keeps running.

In modern JavaScript, the cleanest way to write this is with async and await:

async function getData() {
  let response = await fetch("https://example.com/data.txt");
  let text = await response.text();
  console.log(text);
}

The word async marks a function that may pause. The word await says: "Wait right here until this promise is resolved, then keep going." The code reads top to bottom, just like normal code, even though it is actually pausing in the middle.

Behind await is a Promise — a little receipt that says, "A value will arrive later." A promise is either pending, resolved (success), or rejected (failure). You can chain them with .then and .catch, or simply await them inside an async function.

This is one of the harder ideas in JavaScript. Be patient with yourself. Once it clicks, the whole web opens up: fetching data, saving to the server, animating frames — all of it becomes possible.

Key Ideas

  • Asynchronous code starts something and continues without blocking.
  • Promises represent values that will arrive later.
  • async marks a function that can pause; await pauses until a promise resolves.
  • Slow operations (network, files) are usually asynchronous in JavaScript.

Try It Yourself

  1. Write an async function that awaits a promise which resolves after one second.
  2. Try to fetch a URL with fetch and print the status code.
  3. What happens if you use await outside an async function?

Part Three · Masters · Chapter Fourteen

Secret Codes and Patterns

Finding shapes inside text.

Sometimes you need to find all the email addresses in a giant wall of text, or all the phone numbers in a document, or all the dates in a list. You could write a loop and check every character by hand, but there is a better tool: the regular expression.

A regular expression is a tiny language for describing patterns. You write the pattern once, and the computer finds every match. Here is one that finds any sequence of digits:

let digits = /\d+/g;

let text = "I have 3 cats and 12 goldfish.";
console.log(text.match(digits)); // → ["3", "12"]

The slashes mark the start and end of the pattern. \d means "any digit." The + means "one or more." The g at the end means "global — find all matches, not just the first."

Regular expressions can describe almost any pattern. Here is one that matches a simple email address:

let email = /\S+@\S+\.\S+/g;

console.log("Contact: ada@example.com or pip@school.org".match(email));
// → ["ada@example.com", "pip@school.org"]

Regular expressions are powerful, but they have a reputation for being cryptic. Start with the common pieces: \d for digits, \w for word characters, \s for spaces, . for any character, + for one-or-more, * for zero-or-more, and | for "or." Build slowly, test often, and read the pattern out loud to yourself.

Key Ideas

  • Regular expressions describe patterns in text.
  • The g flag finds all matches, not just the first.
  • match searches a string; replace rewrites it.
  • Start with small patterns. Test them on real strings before combining them.

Try It Yourself

  1. Write a regular expression that matches all the words starting with "b" in a sentence.
  2. Find all the numbers in a paragraph that contains dates and prices.
  3. Use replace with a regular expression to turn "cat" into "dog" everywhere.

Part Three · Masters · Chapter Fifteen

Drawing with Code

When the DOM is not enough.

You can draw with HTML and CSS — position a div here, color a box there. But when you want to draw a thousand particles per second, or a smooth curve, or a game, you need something faster. You need a canvas.

The <canvas> tag is a blank rectangle in a web page. JavaScript can paint on it, pixel by pixel, shape by shape, at very high speed. First you grab a drawing context, and then you use it like an artist's sketchbook:

let canvas = document.querySelector("canvas");
let cx = canvas.getContext("2d");

cx.fillStyle = "tomato";
cx.fillRect(10, 10, 100, 50);

cx.strokeStyle = "steelblue";
cx.lineWidth = 4;
cx.strokeRect(150, 10, 100, 50);

You can draw lines with moveTo and lineTo. You can draw circles with arc. You can draw text with fillText. You can draw pictures with drawImage. And you can rotate, scale, and move the whole scene with transformations.

For animation, you use a function called requestAnimationFrame, which asks the browser to call your drawing function about sixty times per second:

function loop() {
  cx.clearRect(0, 0, canvas.width, canvas.height);
  cx.fillRect(Math.random() * 500, Math.random() * 300, 20, 20);
  requestAnimationFrame(loop);
}
requestAnimationFrame(loop);

Canvas is how you build games, data visualizations, image editors, and generative art. The whole of the visual web lives here.

Key Ideas

  • <canvas> is a paintable surface; getContext("2d") gives you the brushes.
  • fillRect, strokeRect, arc, lineTo — these are your basic shapes.
  • requestAnimationFrame lets you draw smooth animation.
  • Transformations (translate, rotate, scale) let you draw in any orientation.

  2. Animate a ball that bounces off the edges of the canvas.
  3. Draw your name in big letters using fillText.

The Internet Adventure

How your programs talk to the wider world.

Every time you visit a website, two computers have a conversation. Your computer asks for something, and another computer — far away — answers. The rules of that conversation are called HTTP, and learning them is the key to building web apps that talk to servers.

An HTTP request has a method (usually GET or POST), a URL, and sometimes a body. The reply has a status code (200 means OK, 404 means not found) and its own body. In the browser, you make requests with a function called fetch:

let response = await fetch("https://example.com/data.json");
let data = await response.json();
console.log(data);

That one function can fetch data, send data, delete data — the whole vocabulary of the modern web. It returns a promise, which is why we use await.

Often, the data comes back as JSON — a text format for objects and arrays. It looks almost exactly like JavaScript literals, which makes it easy to convert back and forth with JSON.parse and JSON.stringify.

When you combine fetch with the DOM, you get single-page applications — sites that update smoothly without reloading. When you add Node.js on the server side, you can build the server too. The internet, in the end, is just a very large conversation between programs. And now you know the language.

For security, browsers guard their users carefully: a web page can only make requests to its own domain unless the server explicitly allows otherwise. Always respect those rules. They are what keep the web safe.

Key Ideas

  • HTTP is the protocol for requesting and sending resources.
  • fetch makes HTTP requests and returns a promise.
  • JSON is the standard text format for structured data.
  • Browsers protect users with same-origin rules and the CORS headers.

Try It Yourself

  1. Use fetch to load a text file and print its contents.
  2. Fetch a JSON file and print one of the fields.
  3. What does a 404 status mean? What about a 500?

The Little Dictionary

Every new word you met along the way.

Array
An ordered list of values, written with square brackets: [1, 2, 3].
Asynchronous
Code that starts something slow and continues without waiting for it to finish.
Binding
A name tag you stick on a value, created with let or const.
Boolean
A value that is either true or false.
Bug
A mistake in a program that makes it do something wrong.
Call stack
The list of functions that are currently running, one inside the other.
Canvas
A rectangular surface in a web page that JavaScript can paint on.
Class
A blueprint for creating objects with shared structure and behavior.
Closure
A function that remembers the variables from where it was created.
Constant
A binding whose value cannot be reassigned, created with const.
Debugging
The art of finding and fixing bugs.
DOM
The Document Object Model — the tree of elements that makes up a web page.
Event
Something that happens in the browser, like a click, a keypress, or a page load.
Function
A reusable block of code that can take arguments and return a value.
Higher-order function
A function that takes another function as an argument or returns one.
JSON
A text format for storing and sending structured data.
Loop
A construct that repeats a block of code until a condition is met.
Method
A function that belongs to an object.
Object
A collection of named values, called properties.
Parameter
A named slot in a function definition for receiving an argument.
Promise
An object representing a value that will arrive in the future.
Regular expression
A compact language for describing patterns in text.
Scope
The part of a program where a binding is visible and usable.
String
A piece of text, written between matching quotation marks.
Variable
Another word for binding — a name for a value that can change.
